Super Roc — Roc-Solid AI Performance

Local inference engine

An LLM inference engine for Strix Halo: Ryzen AI Max+ 395 systems with the Radeon 8060S GPU (gfx1151) and up to 128 GB of unified memory. GGUF models, 4-bit ROCmFP4 builds, MTP and DSpark drafting, and a prompt cache that resumes from any earlier conversation state.

Engine

What Super Roc adds

  • ROCmFP4 / ROCmFPX tensor types(GGUF types 100 and above) in the loader, the kernels and the serving path, including spill-free dense prefill and decode kernels for the 4-bit types.
  • superroc-quantA standalone GGUF quantizer for the ROC recipes (STRIX, STRIX_LEAN, LEAN, COHERENT, FAST and the G4 variants) with protect rules, a tensor census, manifests and streaming output. For the ROC recipes its output is byte for byte the same as the ROCmFPX llama-quantize. See docs/superroc-quant.md.
  • More model familiesqwen35 / qwen35moe ROC builds (Qwen3.8, KAT-Coder, Ornith, MiniCPM-V, OxCoder, Agnes, Nex, BTL-4, MiMo), bailingmoe3 (Ling-3.0-flash and Ling-3.0-flash-VL), lfm2 / lfm2moe (LFM2.5), flint (Flint 40B-A2.5B: sliding-window and position-free attention layers with attention sinks), llama (Nanbeige4.3-33B-Base, serve-only: limits) and Muse Glimmer.
  • DraftingEmbedded and sidecar MTP heads with a per-request draft depth and exact verification, the DSpark drafter, and prompt-cache snapshots that keep working while a drafter is on.
  • Stock MoE GGUFsqwen35moe files with Q4_K, Q5_K, Q6_K or Q8_0 routed experts, such as common Q4_K_XL builds and ROCmFPX Q8 files, run on the mixture-of-experts kernels with the expert choice kept on the GPU.
  • Speed settingsA 4-bit prefill route for dense ROCmFP4 files, a tensor overlay and a routed-expert count for mixture-of-experts files, and prompt-lookup drafting (options).
  • Tool callsIn each model's native format (Qwen, GLM-style, Ling, Flint), constrained by a grammar built from the request's tools where the format allows it.
  • HardeningHTTP header and body read deadlines and size caps, constant-time API key comparison, checked HIP kernel launches, and validation in the GGUF reader, configuration and weight binders.

Quick start

Run it with Lemonade

On a Strix Halo machine running Linux with ROCm and Lemonade, install the packages listed under Without Nix, then:

git clone https://github.com/kingjones30/superroc.git
cd superroc
tools/lemonade/setup.sh
lemonade pull LFM2.5-1.2B-Instruct
lemonade chat LFM2.5-1.2B-Instruct

tools/lemonade/setup.sh is optional: it checks the machine, builds Super Roc, installs it in /opt/superroc (with sudo for that step only when needed), points Lemonade at it and adds the Super Roc model list, keeping any model lists you already have. Run it again at any time. --dry-run shows what it would do, --undo switches Lemonade back to its own llama.cpp, and --help lists the options. The same steps by hand are in docs/LEMONADE.md. Models Super Roc does not run keep running on Lemonade's own llama.cpp.

Without Lemonade, build it (Build from source) and serve a model directly (Run).

Build from source

Linux x86-64 on AMD Strix Halo (gfx1151) is the supported target.

With Nix

nix build
./result/bin/superroc diagnose
./result/bin/superroc serve llm --model /path/to/model.gguf

Without Nix

Install a C++20 compiler, CMake 3.21+, Ninja, pkg-config and the ROCm HIP development libraries (ROCm normally installs under /opt/rocm), then:

sudo apt install build-essential cmake ninja-build pkg-config \
  libicu-dev libcurl4-openssl-dev libssl-dev libpng-dev libjpeg-dev libwebp-dev ffmpeg

# ROCm libraries, named as AMD's repository ships them.
sudo apt install hipblas-dev hipblaslt-dev rocblas-dev \
  hipcub-dev rocprim-dev rocwmma-dev

cmake --preset release -DCMAKE_INSTALL_PREFIX="$HOME/.local"
cmake --build --preset release --parallel 4
./build/release/superroc diagnose

cmake --install build/release installs Super Roc, its runtime data and the license notices.

Serve

Run

Serve a model (here KAT-Coder-V2.5-Dev Abliterated with its embedded MTP drafter, see its card):

./build/release/superroc serve --host 127.0.0.1 --port 8080 llm \
  --model /path/to/KAT-Coder-V2.5-Dev-Abliterated-MTPq8-Q4_0_ROCMFP4_STRIX_LEAN.gguf \
  --served-model-name kat-coder --context 131072 --think off --speculative mtp -d 3 --min-draft-tokens 1

Then ask it something through the OpenAI-compatible API:

curl http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model": "kat-coder", "messages": [{"role": "user", "content": "Write a Python function that reverses a list."}]}'

Recipes

A tuned setup can travel with the model file as superroc-recipe.json: engine variables, sidecar files (such as an int4 prefill route or a tensor overlay) and tuning flags. Put the recipe and its sidecars next to the model and start with --recipe auto; flags on the command line still take precedence:

./build/release/superroc serve --host 127.0.0.1 --port 8080 llm \
  --model /path/to/Qwen3.8-27B-UD-Q4_K_XL.gguf --dflash-model /path/to/Qwen3.8-27B-DFlash2-Q4_K_M.gguf \
  --speculative dflash2 --recipe auto

The recipe for that file is on Hugging Face at kingjones777/Qwen3.8-27B-SuperROC-Recipe. The format and its rules are in docs/recipes.md; measured results are in docs/BENCHMARKS.md.

Anthropic API and Claude Code

The same server speaks the Anthropic Messages API:

curl http://localhost:8080/v1/messages \
  -H "Content-Type: application/json" \
  -H "anthropic-version: 2023-06-01" \
  -H "x-api-key: none" \
  -d '{"model": "kat-coder", "max_tokens": 64, "messages": [{"role": "user", "content": "Write a Python function that reverses a list."}]}'

It supports streaming SSE, system prompts, tools with tool_result round trips, thinking blocks, count_tokens, and prompt-cache usage fields. The request and response shapes are in docs/SERVER.md.

Claude Code works against the server with these variables:

export ANTHROPIC_BASE_URL=http://localhost:8080
export ANTHROPIC_AUTH_TOKEN=none
export ANTHROPIC_MODEL=kat-coder
export ANTHROPIC_SMALL_FAST_MODEL=kat-coder
claude

ANTHROPIC_MODEL is the name the server was started with (--served-model-name).

For Open WebUI, VS Code, the OpenAI SDK and Responses-API clients, set the API base URL to http://localhost:8080/v1. Anthropic SDK clients and Claude Code use http://localhost:8080 as the base URL. Chat Completions and Responses support text, images, function tools, structured output and streaming. The server uses the model's native context by default; --context N sets the context per session and --max-tokens N a default response limit that clients can override (reasoning tokens count toward it). The full API contract is in docs/SERVER.md and the command line in docs/CLI.md.

Lemonade

Super Roc runs inside a stock Lemonade install today: point Lemonade's llama.cpp ROCm slot at the Super Roc launcher and add the Super Roc model list.

tools/lemonade/setup.sh                # build, install and configure in one step

or by hand:

tools/lemonade/install.sh --superroc ./build/release/superroc --prefix /opt/superroc
lemonade config set llamacpp.rocm_bin=/opt/superroc/lemonade

Models that Super Roc does not run go to the stock llama-server unchanged. Setup, the model list and troubleshooting: docs/LEMONADE.md.

Honest notes

Known gaps

  • Muse Glimmer loads, but its DFlash drafter does not yet, and without it Super Roc generates more slowly than llama.cpp (ROCmFPX build) on that model.
  • Several GPU tests and tools read a model file; they take its path from an environment variable and fail without it.
